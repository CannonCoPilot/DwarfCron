New Rules Rebuild

Port the New Rules into the tool exactly as the Food Web Explorer defines them. The same rules grow every season's casts, link the season's layers, and decide what the tool writes in play. The explorer is the specification, and rig tests check that the tool follows it.

Open for you

Q1Evil apexes: matched by their raws, or added by wiring only?

The engine lets the grimeling, nightwing and harpy past the unliving filter, so they match their raw biomes. The explorer, and so New Rules, adds them only where they are wired (the 'reach' wire for the grimeling at an evil marsh or swamp). Today the two disagree on that path, and the parity tests don't cover it.

Recommendation: follow the explorer's way. The port is exact, and the explorer is the spec, so the engine stops admitting evil apexes by their raws. If you want the raws' way instead, the explorer changes first and the engine follows.

Q2Where the one copy of the rules lives

Each rule is kept by hand in three places today: engine Lua, desk Python and explorer JS. Every rule from 17 to 20 Oct took three edits, and the evil-apex path above has already drifted.

Recommendation: a rules file in the seasonal-wildlife repo (rules/new-rules.json). A generator turns it into a Lua table that ships in the package, so nothing is read from disk at run time and nothing can fail on load. The desk and the explorer read the same file. The rules keep the explorer's content and change only where they are stored.

The rebuild, in order

Branch v8-newrules from c125091; release key 8.0.0. Each phase ends on a check that must pass before the next one starts. A phase is finished only when it is in the packaged zip, not on the dev copy.

  1. A

    The explorer becomes the full spec

    • Build G2 and G3 into the explorer and the desk properly: the land-flying lists, land-flying grown on New Rules, and the step that links the layers. Today they exist only as the analysis prototype.
    • Store the rules once (Q2). Every table moves into the rules file, and the desk and the explorer load it: diets, bars, never-lists, role, guild and habitat overrides, extra and limited biomes, evil apexes (Q1), wetland ground, vermin types and sides, LINK_AS, and the apex lists.
    • Regenerate the targets table from the explorer and publish explorer v42.

    ExitDesk parity is exact. The explorer reads the rules file. The targets come from the explorer itself and agree with the prototype, or the difference has been reported to you. Done 20 Oct: rules file sw 8cdae46 (40 tables, engine 0 drift, G2 pending for Phase B); desk and explorer read it with unchanged output; parity exact with G2; explorer v42.

  2. B

    One feeding test in the engine

    • Generate RULES (Lua) from the file. RULES.eats(a, b, layer, crossLayer) returns the passing families and the reasons, as the explorer's New Rules does.
    • Every caller goes through it: cast growth, the cast's edge set, the hunting-pair filter, and vermin selection. Predicates that no New Rules family uses are removed, and the conformance test below shows nothing depended on them.
    • Conformance test: the explorer exports every (eater, eaten, layer, cross-layer) verdict, with its families, on the six forts. The engine harness computes its own, and the two must agree on every pair.

    ExitConformance is 100% on all six forts. The fixes, controls, water, onoff and gui suites are green. luacheck stays at 37 or below. Done 20 Oct: the engine's tables are generated from the rules file (V7.RULES, sw b14b5eb); V7.NR, the Lua port of New Rules, agrees with the explorer on all 385,796 pairs (55,179 linked) and the check catches deliberate mutants; Q1 applied with the explorer's reach wire (sw bcc7189). Every suite green, luacheck 37. Routing the callers moved to the phases that change them: cast growth, the edge set and vermin selection in C, the hunting-pair write in D, each through an adapter from the engine's pool entries to the explorer's records, checked against the explorer on the fort's own pool.

  3. C

    The cast builder on New Rules

    • Growth tests RULES on all seven layers, land-flying included (G3). Slot tables, seeds, cavern pairing and sentient seats are kept as they are (G1, G4).
    • The final step lists the season's cross-layer links among the land-ground, land-flying and water casts.
    • The engine scores holes the same way the analysis does: surface joined per season, caverns per cast, predators by role.

    ExitGiven the same site and year seed, the engine and the explorer build the same 28 casts and the same cross-layer links. Run offline in the engine harness over 200 years, the engine's hole counts equal the targets table exactly.

  4. D

    What the tool writes in play

    • The relation write covers the New Rules pairs among the units present. That means hunting pairs within a layer, mass-and-numbers pairs, and the cross-layer pairs from Phase C.
    • Vermin classes (SWV_type@SIDE) and DF's diet tokens come from RULES' vermin verdicts.
    • Verdicts are cached per fort and cast, so each write is a table lookup and stays under FUSE's 250 ms warning.

    ExitA rig probe on a new embark, compared with the explorer's link set for that fort's own pool and casts. Every written relation and vermin class is a New Rules link, every New Rules link among present units is written, and no pass goes over budget.

  5. E

    Rig tests: does the tool follow New Rules?

    • New embarks only: startdwarf 50, caverns breached at the start, embark size 4, and a receipt that each fort's subjects are on the map. v7.6.6 and v8 run on the same tiles, with 5 reps per arm.
    • Links: at embark and at each season change, the tool's written relations and vermin classes are dumped and diffed against the explorer's New Rules links for that fort's pool and casts. The test passes only with nothing extra and nothing missing.
    • Holes: the casts the tool built are scored, and the holes compared with the explorer's prediction for the same casts. With identical casts the counts must be identical. Across reps the rates must sit with the targets table's.
    • Kills: every predator kill and every vermin eaten is checked as a New Rules pair. Frame time is recorded for each pass.

    ExitLinks and holes match on every rep, with zero kills outside New Rules and the frame budget held. A rep with no data is marked pending, not passed.

  6. F

    The interface catches up

    • Rev 5's step 2: a Casts view (seven layers × four seasons) in the window and the web page. It now shows each cast's links, its cross-layer links, and why each exists. Every switch goes in the controls registry.

    ExitThe window and web harnesses are extended and green, and the panel and page round trips work on the rig.

  7. G

    Package and release

    • Validator claims for v8 (casts, rules conformance, writes, holes), then validate-full at 0 FAIL.
    • Build the zip and install it as a player would, with the dev copy removed. Play one packaged year on a new fort, with off at the end.
    • Docs (USAGE, STATE, HANDOFF, changelog); merge when you say so.

    ExitThe packaged zip passes its year. This is the finished deliverable.
